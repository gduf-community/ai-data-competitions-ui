### 统一加载：欧拉之桥

2026-10-25 起，全页和局部加载统一使用 [EulerBridgeLoader / LoadingStatus](../src/components/shared/euler-bridge-loader.tsx)。覆盖路由加载、表格/卡片/图表取数、检索、表单提交、上传、后台刷新、退出登录及 Toast。原图的四个节点代表不同学科，几何路径代表协作和知识流动。原图可拆成四节点、水平/垂直轴与两条对角连接、外侧蓝弧、中央蓝色 S 形桥、铜色内椭圆及右上拱弧。加载版本将右—上、下—左两组端点连接，重组为经过四节点的一条闭合回路；原有 Logo 和 favicon 沿用现状。

全页默认 `96px`；按钮使用 `16px`，上传遮罩和局部状态按空间使用 `16–32px`。`size≤24` 的紧凑版本每节点 `8` 粒子、线宽 `3.2`，较大版本每节点 `32` 粒子、线宽 `2.1`，避免小图标承受完整尺寸的粒子开销。`tone="inherit"` 继承文字颜色，适用于主按钮及图片遮罩；普通页面状态保留蓝铜双色。`Button.loading` 仅负责图标及 `aria-busy`，沿用调用方已有的文案、禁用条件和请求逻辑。纯文字加载提示使用 `LoadingStatus`；赛程、侧栏骨架保留占位布局，配上统一图标，取消独立脉冲动画。

解析重建以用户提供的 1254×1254 原图为依据，是笔画中轴的平滑近似，不代表恢复了原始生成方程。原图节点中心约为上 `(626,205)`、右 `(1051,615)`、下 `(626,1030)`、左 `(209,615)`；按 `x'=(x-130)/10`、`y'=(y-120)/10` 归一化到 `100×100`。节点坐标依次为 `(49.606,8.503)`、`(92.066,49.483)`、`(49.609,91)`、`(7.856,49.482)`，半径 `3.1`。

回路顺序为上 → S 桥 → 下 → 左下外弧 → 左 → 铜色内弧 → 右 → 右上外弧 → 上。S 桥沿原图中轴重建，将首尾接到节点；铜色内弧按原图的左下回绕与右上拱顶重组为左到右的连续曲线。两个外弧使用四分之一椭圆的三次贝塞尔近似，控制柄比例 `κ=4(√2-1)/3`。内弧分段共享控制柄，保证 C1 连续；节点作为转向连接点，节点处保持位置连续。以下控制点可直接复现静态 SVG；各段使用 `B(t)=(1-t)³P₀+3(1-t)²tP₁+3(1-t)t²P₂+t³P₃`，`0≤t≤1`。

静态线条与粒子轨迹使用同一份闭合几何参数；两种颜色只是回路的两个连续区段。

动效参考 [Paidax01/math-curve-loaders](https://github.com/Paidax01/math-curve-loaders)，来源版本 [`70f4e00a6d452532039ff7c2ccb4c379ec90c772`](https://github.com/Paidax01/math-curve-loaders/blob/70f4e00a6d452532039ff7c2ccb4c379ec90c772/main.js) 的参数轨迹、粒子衰减与动画帧方法，独立适配为 React 组件；不引入整个画廊或额外运行依赖。默认 `96px`，四节点同时各发出一束 `32` 粒子的尾迹。轨迹按四节点拆成四段，每束起点使用节点在整圈中的实际弧长偏移，不使用等分相位；四束均沿同一闭合回路运动，经过蓝铜分界时随线条换色。粒子循环 `4600ms`、拖尾比例 `0.16`，缩短尾迹以保留四束之间的留白。整个图形围绕 SVG 的 `(50,50)` 顺时针自转，`20000ms` 一圈；线条、节点和粒子一起转，外层加载文字保持不动。几何形状不呼吸、不变形，轨迹按弧长预采样，在节点继续前进。

浅色使用墨蓝 `#0A284C`、古铜 `#B48746`；深色使用较亮同色相 `#8BAFD3`、`#D4AD72`，透明背景、不复刻原图纹理。服务端首屏直接输出静态 SVG；`prefers-reduced-motion: reduce` 隐藏粒子、停止自转并恢复正立方向，强化静态线条，恢复普通动效时从四节点重新出发。后台标签页同时暂停粒子和自转，回来后继续；组件卸载清理动画帧和监听器。外层保留“正在加载…”及 `role="status"`，图形对辅助技术隐藏；不设置最低展示时长，不延迟真实 Suspense 内容替换。

[动效录制片段（4.6 秒）](./assets/euler-bridge-loader-preview.gif)来自真实加载组件的独立浏览器预览，只包含加载图标与状态文字，不包含业务数据。

## 交互约定

- 复用现有主题变量、字体、间距、状态标签和基础组件，保持深浅色一致；状态文案与 API 枚举一致。
- 官网报名、填写校内资料、查看微信推文是不同动作，按钮应说清目的。
- 加载、空数据、拒绝和故障分别呈现；失败保留输入并提供可操作重试，不把错误显示成空列表。
- 提交中阻止重复操作；撤回、驳回、取消、删除等操作的确认、原因和失败恢复按具体组件维护，逐入口验收，最终结果由 API 校验。
- 优先语义元素、键盘操作、焦点顺序、标签和替代文本；移动端表单、弹窗与主要 CTA 不能溢出。
- 动效服务信息层级，兼顾 `prefers-reduced-motion`，不阻塞表单和审核。

搜索与分页沿 URL 和[搜索协议](./搜索协议.md)，完整数组与当前样本的范围应清楚呈现。社团保存/发布区分草稿、更新公开内容和下线后重发，上传中显示阻塞原因；409 冲突保留正文供核对，不以成功 Toast 替代真实响应。图片异常保留标题/说明和重试，不能用占位封面通过保存验证。
