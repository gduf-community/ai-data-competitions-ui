# 开源协作指南

本文档说明 `ai-data-competitions-ui` 的协作方式、提交边界和 PR 要求。本仓库直接维护完整 Web、组件、SSR、BFF、前端测试与文档；独立 API 仓库负责可信后端、权限、事务、数据库与存储。旧 Mock UI 的反向同步流程已退役。

## 可以提交什么

欢迎提交以下类型的修改：

- 页面视觉优化：布局、色彩、间距、响应式适配和深浅色细节。
- 交互优化：筛选、搜索、弹窗、抽屉、导航、状态反馈。
- 通用组件抽象：比赛卡片、状态徽标、表单项、表格、空状态等。
- 可访问性改进：语义标签、键盘操作、焦点状态、对比度和替代文本。
- 前端与传输回归：使用合成 API 响应/数据验证边界状态和空数据状态。
- 文档补充：功能说明、开发说明、截图、PR 示例和组件约定。

## 不应提交什么

请不要提交以下内容：

- 真实学生信息、报名记录、联系方式或内部业务数据。
- 数据库/对象存储管理凭据、认证签名、后端事务与授权实现。SSR/BFF 仅负责展示与 HTTP 传输。
- 密钥、Token、Cookie、服务器配置和任何私有环境变量。
- 与公开 UI 展示无关的大型业务逻辑。
- 未经脱敏的截图、录屏和日志。

## Pull Request 要求

提交 PR 前请尽量完成：

```bash
pnpm install --frozen-lockfile
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

PR 描述建议包含：

```markdown
## 修改内容

- 
- 

## 影响范围

- 

## 验证方式

- [ ] pnpm dev
- [ ] pnpm build
- [ ] pnpm lint

## 截图或录屏

## 备注
```

## 分支与提交规范

推荐分支命名：

```bash
feat/home-hero-section
fix/mobile-navbar-layout
docs/update-readme-showcase
refactor/competition-card
```

推荐 Commit 格式：

```bash
feat: 优化首页 Hero 展示区域
fix: 修复移动端导航折叠异常
docs: 补充开源协作文档
refactor: 抽离赛事卡片组件
```

## UI 修改截图要求

涉及视觉变化时，请尽量提供：

- 修改前截图。
- 修改后截图。
- 桌面端截图。
- 移动端截图。
- 必要时提供短录屏说明交互状态。

截图请避免包含真实学生信息、真实报名记录、内部后台地址或其他敏感内容。

## 维护原则

- 公开仓库优先保证可预览、可复用、可协作。
- 完整 Web 业务流程在本仓维护，可信授权与事务只在 API 执行。
- UI 变更通过合成联调数据与前端回归呈现；接口需求明确契约和精确 companion SHA，不用 Mock fallback 掩盖 API 故障。
- 文档、截图和模板也是开源项目体验的一部分，应与代码同步维护。
