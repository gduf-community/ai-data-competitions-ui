# 浏览器兼容策略与测试基线

兼容验收优先覆盖“学生在微信/手机发现比赛并报名，老师在桌面 Chrome/Edge 审核”。以下为验收目标，尚未给出当前版本真机通过结论。

| 场景 | 验收目标 |
| --- | --- |
| 桌面管理 | 最近两个大版本 Chrome、Edge 的登录、审核、筛选、SQL 与导出 |
| 移动核心路径 | iPhone Safari、Android Chrome、iOS/Android 微信 WebView 的比赛、报名、问答与上传 |
| 次级浏览器 | QQ、夸克、UC、360 的核心流程；按实际引擎版本记录 |
| 基础可用 | Safari/Firefox 公共展示与基础交互；不支持 IE |

## 实现与声明边界

当前 [package.json](../package.json)没有单独的 Browserslist 支持声明，不能继承旧全栈文档中的 `Android >= 8` 或 Safari 15+ 为已验证最低版本。Next.js 16、Tailwind 4 和实际使用的 API/CSS 特性共同决定运行下限；操作系统版本与浏览器引擎必须分开记录。

共享 JSON 客户端使用 `signal.aborted` 并兼容缺失 reason；表单默认值沿既有工厂产生，不要求 structuredClone。现有回归覆盖相关缺失 API 情形，但不代表 Safari/微信真机通过。

## 验收清单

1. 在 375/390/414/768px 与桌面检查导航、表格、弹层、输入法和长文本；记录设备、系统、浏览器引擎、精确 Web/API SHA。
2. 核验登录/刷新会话、报名必填/团队成员/重复提交、问答输入、图片上传失败/重试、下载和已读通知。
3. 核验 API 故障、拒绝权限、写后刷新与返回操作；测试环境仅用合成身份。
4. 检查键盘、焦点、触控、替代文本、对比度与减少动效；主流程失败作为阻塞项。

自动回归与 `pnpm build` 只说明其覆盖范围，真实浏览器、入口、网络和生产部署另留记录。[Web #2](https://github.com/gduf-community/ai-data-competitions-ui/issues/2)跟踪兼容性工作。
