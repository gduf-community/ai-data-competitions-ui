## P0：数据分层与分页

| 层级 | 路径 | 加载要求 |
| --- | --- | --- |
| A | /awards | 年度与赛事聚合，无证书图片节点、无全量证书查询 |
| B | /awards/year/[year] | 指定年度赛事/等级统计，无证书图片节点 |
| C | /awards/year/[year]/[competitionId] | 同时限定年份与赛事，默认每页 24 条，服务端硬上限与稳定游标 |
| D | /awards/[id] | 单张证书详情，保留旧链接及大图 |

- A/B 消费数据库聚合结果，不能先取全量证书再在 SSR 或浏览器统计；批准状态、有效赛事关联和计数口径与 C 一致。
- C 将原“实测过大再考虑分页”更新为必须实现服务端分页；唯一证书 ID 作为排序并列的最终键，不解析其他页图片 URL。完整等级小计由聚合结果提供，不能拿当前页计数冒充赛事总数。
- 年份、赛事 ID、游标及年/赛事不匹配要明确校验，非法输入或无公开记录采用冻结的 404/错误契约；错误不能退回全站查询。分页前进、返回、刷新、分享直达的状态可恢复。
- 新增公开 GET 纳入 permittedPublicServerRead 的精确白名单，遵循服务身份与访问策略；不得使用任意路径放行或绕过 fail-closed 网关。原 /api/awards 保留兼容。
- 首页荣誉墙仅使用管理员精选，最多 20 条，精选开关与长廊公开资格独立。D 旧地址兼容，详情导航另有 Web #151 的 P2 任务。

## P0：首批图片预算与近视口挂载

| 环境 | 数量预算实验参考（非硬上限） | 观察扩展视口 |
| --- | ---: | ---: |
| 移动端 | 2 张 | 256px |
| 桌面端 | 4 张 | 320px |
| Save-Data / 2G | 1–2 张 | 0px |
| 单证书详情 | 当前大图 | 按详情需要 |

**真实首屏可见内容优先，2/4/1–2 张仅作实验参考，不是硬上限或最高优先级规则。** 首屏有 3 张可见证书时不为移动预算延迟第三张；首张证书在折叠以下不因下标为 0 而强制 high。LCP 可能是文字，须按元素与阶段归因。分页仍默认 24 条；查询规模与网络竞争分别控制。

- 首屏/LCP 候选从首个 HTML 尽早可发现，不被普通占位、hydration 或 observer 阻塞；仅归因确认的关键图提升优先级，检查 preload 与实际 URL/尺寸一致，避免重复下载。其他图片用 IntersectionObserver 控制挂载，未进扩展视口不提前请求；开始加载后不卸载。
- 无 IntersectionObserver 或连接信息 API 时有可用回退，不能永久占位；加载、失败、空地址与 URL 变更可区分。单图失败保留文本和详情入口。
- 保留 next/image、原生加载/解码与动态授权素材 unoptimized；可见图及时正常加载，最高优先级以 LCP 归因确定，不批量 priority/preload，非关键图可低 Fetch Priority。
- 主要复用 src/components/shared/lazy-fill-image.tsx；普通失败回退、授权 URL 识别和视口策略保持清楚，首页、C、D 可分别配置。优先最小修改，不把荣誉网格策略强加所有图片消费者。
- 不引入客户端下载队列、Adaptive Scheduler、Base + Refinement 或自定义解码器。nothing-new 的来源尚需补可追溯链接，不能把外部“已验证”当成本项目证据。

## P1：BFF 条件请求与撤回安全

- 仅对公开图片 GET 受控转发 If-None-Match，保持 ETag、Cache-Control、Content-Type 及 304；304 不转成 200 或错误，不构造响应正文。
- 继续采用 Cache-Control: public, max-age=0, must-revalidate。API 在版本与当前公开资格检查通过后才可 304，且不读取 OSS 正文；200 保持读取前后复核，撤回/旧版本后续新请求为 404。
- 不将动态授权证书交给 Next 长期图片缓存或长期 CDN 缓存。测试浏览器暖缓存、弱/多 ETag 协商、304 与撤回竞争、API/BFF 429/503 及 Retry-After。

304 仍执行当前公开资格复核，数据库成本未必下降，报告分别量化 SQL/OSS/字节。指纹化 JS/CSS 与版本固定公开字体/静态图才适合长期 immutable；HTML/RSC、动态 JSON 和身份相关响应遵循现有隔离语义，不能套同一静态缓存规则。

## P1：尺寸变体与入口核查

- 按真实 CSS 宽度/DPR 选择已有 320/960/1920px WebP，网格与详情分场景，保留资格/版本、历史缺失变体回退。unoptimized 下仅 sizes 不保证产生 srcset/缩小下载；以 currentSrc、像素、字节和清晰度实测，必要时最小调整 DTO/原生响应式消费，不启用长期 Next 图片缓存或新编码。该 P1 与 P2 去裁剪分别验收。
- Nginx 主导核查在 API 仓库记录受限配置；先查实际版本/模块、HTTP/2/TLS、连接复用、缓冲/临时文件、Content-Encoding/Vary 与缓存头。sendfile 不直接改善 Node/BFF 的 OSS 转发；不复制 http2 on; 或静态扩展名 location，不覆盖动态图片、权限和安全头。
- 只对 HTML/JSON/CSS/JS 等文本评估 gzip/Brotli，WebP/JPEG/PNG/woff2 不重复压缩；受资源限额约束，一项一测 CPU/内存/延迟，已满足或无收益可以保持现状。不在本次修改/重载 Nginx，不引入 CDN、HTTP/3。

## 验证与关闭条件

开发前由 API #148 开始固定负载基线采集；Web #64 最终汇总适用证据，不到交付末尾才开始测量。

- 数据：0/10/50/200/1000 张，覆盖单赛事集中、多赛事分散及多年度；统计以证书记录数计，不混同官方获奖名单或去重人数。
- 浏览器：390×844、1440×900；正常/受限 4G、CPU 限速，冷/暖缓存；快速滚动、返回、分页与路由直达，每组至少 5 次独立采样。
- 指标：文档/图片 TTFB、LCP 元素和子阶段、INP/具体交互、CLS、初始/滚动图片请求数、字节、304/SQL/OSS计数、可见图片完成时间、失败率、Long Task 与页面 P95。相同条件 P95 不回退；首屏图片字节减少 40% 是待测优化目标。
- 安全/故障：Approved/Pending/Rejected、精选独立开关、撤回/重新发布、多引用、旧版本、非法/历史/跨比赛 key、匿名/登录、DB 超时、OSS 失败、429/503。数据错误、零记录和单图错误分开反馈。
- API/Web 资源与压力证据在受控环境采集，保持现有限额；无 OOM 不足以验收，需查看 MemoryHigh 回收和持续内存压力。版本、条件、原始结果、发布/监控/回滚说明分别记录。
- 本计划入库不授权直接上线、迁移、生产压测或历史图片回填。
