# competition-Q-A-website-ui

学院竞赛管理与问答平台的公开 UI 仓库。

本仓库用于沉淀学生门户、竞赛信息展示、荣誉成果展示和通用前端组件，方便外部贡献者参与界面优化、交互改进和通用组件建设。

> 本仓库只包含公开 UI、通用组件和演示数据，不包含生产环境后端、真实业务数据、权限系统、部署密钥或内部管理逻辑。

## 项目定位

`competition-Q-A-website-ui` 是学院竞赛管理与问答平台的公开前端 UI 子仓库，主要服务于以下目标：

- 展示学院竞赛平台的门户视觉风格。
- 沉淀可复用的页面结构和通用组件。
- 支持社区通过 Issue 和 Pull Request 参与 UI 改进。
- 为后续页面扩展提供稳定的设计与组件基础。
- 在不暴露私有业务逻辑的前提下开放部分前端建设过程。

如果你希望贡献页面样式、组件交互、响应式适配、无障碍体验或文案优化，欢迎提交 Issue 或 Pull Request。

## 功能概览

### 首页门户

首页用于展示平台定位、重点赛事入口、竞赛成果和行动引导。当前包含导航栏、Hero 区域、重点赛事、荣誉展示、CTA 和页脚。

### 赛事展示

赛事展示模块以卡片形式呈现近期可参与或值得关注的比赛，包含赛事状态、赛事类别、报名窗口、主办单位、年份和详情入口等信息。

### 荣誉展示

荣誉展示模块用于呈现奖状作品墙、竞赛达人风采和成果沉淀，突出优秀参赛者、获奖记录和学院竞赛建设成果。

### 通用组件

本仓库沉淀按钮、卡片、弹窗、表单、表格、图表、徽标、导航栏、侧边栏等基础 UI 组件，便于后续页面统一视觉和交互体验。

### 视觉动效

项目包含渐入、错落出现、跑马灯、光晕背景等轻量展示效果，用于增强门户页面的展示质感。

### Mock 数据

当前页面使用前端 Mock 数据支撑独立预览，方便贡献者在不接入真实后端的情况下进行 UI 开发和调试。

## 当前页面

### 首页

首页由导航栏、Hero、重点赛事、荣誉展示、行动引导和页脚组成，用于展示学院竞赛平台的核心入口与整体视觉风格。

### 重点赛事

重点赛事区域以卡片方式呈现比赛信息，突出比赛状态、报名方式、所属部门、年份和详情入口。

### 荣誉展示

荣誉展示区域包含奖状作品墙和竞赛达人展示，用于呈现优秀参赛者、获奖记录和学院竞赛成果。

### 通用 UI

通用 UI 组件用于支撑后续页面扩展，保持按钮、弹窗、表格、表单、徽标、导航等基础体验一致。

## 技术栈

本仓库主要使用以下前端技术：

- Next.js / React
- TypeScript
- Tailwind CSS
- shadcn/ui
- Framer Motion
- Mock 数据驱动的页面预览

## 快速开始

克隆仓库：

```bash
git clone git@github.com:GDUF-quantitative/competition-Q-A-website-ui.git
cd competition-Q-A-website-ui
```

安装依赖：

```bash
pnpm install
```

启动开发环境：

```bash
pnpm dev
```

构建项目：

```bash
pnpm build
```

代码检查：

```bash
pnpm lint
```

如果你使用的是 `npm`、`yarn` 或 `bun`，请根据 `package.json` 中的脚本自行替换命令。

## 贡献流程

1. Fork 本仓库。
2. 基于 `main` 创建新的功能分支。
3. 完成修改并进行本地检查。
4. 提交 Pull Request。
5. 在 PR 中说明修改内容、影响范围和验证方式。

推荐分支命名：

```bash
feat/home-hero-section
fix/mobile-navbar-layout
docs/update-feature-introduction
refactor/competition-card
```

推荐 Commit 格式：

```bash
feat: 优化首页 Hero 展示区域
fix: 修复移动端导航折叠异常
docs: 补充功能介绍文档
refactor: 抽离赛事卡片组件
```

## Pull Request 要求

提交 PR 前请尽量确认：

- 修改范围清晰，不混入无关改动。
- 页面可以正常启动和预览。
- 没有提交真实数据、密钥或内部配置。
- 新增组件具备基本复用性。
- 移动端和桌面端布局没有明显破坏。
- 如修改视觉效果，建议附上截图或录屏。
- 如修改 Mock 数据，说明字段含义和用途。

PR 描述建议包含：

```markdown

如涉及 UI 变化，请在此处附上截图或录屏。
```

## FAQ

### 这个仓库是完整系统吗？

不是。本仓库是公开 UI 仓库，只包含前端展示、通用组件和 Mock 数据。完整生产系统还包括后端服务、数据库、权限控制和部署配置，这些内容不会放在本仓库中。

### 我可以提交 PR 吗？

可以。欢迎提交 UI 优化、组件抽象、文档补充、移动端适配和交互改进类 PR。

### 可以添加真实接口吗？

不建议直接在本仓库添加真实生产接口。如果某个 UI 功能需要接口支持，请先用 Mock 数据完成页面结构，并在 Issue 或 PR 中说明需要的接口字段。

### 可以提交真实比赛数据吗？

不建议。公开仓库应避免提交真实业务数据。演示内容请使用 Mock 数据或脱敏数据。

### 这个仓库会直接部署到生产环境吗？

不会直接作为完整生产系统部署。生产环境部署逻辑由私有仓库负责，本仓库主要承担公开 UI 展示和社区协作功能。
